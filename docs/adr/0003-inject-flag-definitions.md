# ADR-3 フラグの実定義を注入し、要約だけをさせる

| 項目 | 値 |
|---|---|
| 状態 | 採用 |
| 日付 | 2026-09-05 |
| この決定を導いたもの | 品質目標3 説明の正確さ |

**状況** — 候補が使うフラグの意味を説明する必要がある。
モデルに直接書かせると、それらしいが誤った説明が出る。
利用者は「説明を読んで確認した」つもりで誤ったコマンドを実行することになり、
説明が無い場合より害が大きい。

**決定** — `--help` と `man` の両方を実行して出力を統合し、取れた定義だけをモデルへの入力に混ぜる。
プロンプトでは「この定義だけを根拠に要約せよ」と指示し、
定義が取れなかったフラグには「取得できませんでした」と書かせる。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| モデルの知識だけで書かせる | 誤りを構造的に防げない |
| `--help` だけを使う | 足りない。GNU find の `--help` は要約しか出さず、`-name` の説明は man にしかない |
| フラグの説明機能を持たない | 要件 (引数の解説) を落とすことになる |

**結果**

- 得るもの — 説明の根拠が手元のコマンド自身になる。定義が無ければ何も書かれない
- 代償1 — `--help` と `man` の実行が要る。1コマンドあたり最大2プロセス
- 代償2 — man の無い環境では説明が薄くなる
- 代償3 — 束ねた短いフラグ (`-lah`) を分解する処理が要る
