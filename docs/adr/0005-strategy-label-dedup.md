# ADR-5 候補の重複判定に「コマンド名 + サブコマンド + 最初のフラグ」を使う

| 項目 | 値 |
|---|---|
| 状態 | 採用 |
| 日付 | 2026-09-05 |
| この決定を導いたもの | 目的 — アプローチの異なる候補を出すこと |

**状況** — 要件は「アプローチの異なる候補」を出すこと。
プロンプトで指示しないと、モデルは3〜5件すべてを同じコマンドのフラグ違いで埋める。
重複を機械的に除く必要がある。

**決定** — 各候補に戦略ラベル (`strategy`) を持たせ、同じラベルの候補を捨てる。
ラベルがモデルの書式に合わない場合は、コマンドから
「コマンド名 + サブコマンド + 最初のフラグ」で生成し直す。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| コマンド名だけで判定する | `git merge --no-ff` と `git merge --squash` が同一視され、片方が消える。この2つは選択肢として別物 |
| コマンド文字列全体で判定する | フラグの順序や引数名が違うだけで別物として通ってしまう |
| 重複を除かない | 全候補が同じコマンドのフラグ違いになる |

**結果**

- 得るもの — `tr` / `paste` / `awk` / `xargs` のように系統の違うコマンドが並ぶ
- 代償 — 判定が構文的なので、実質同じことをする別コマンドは重複として除けない
