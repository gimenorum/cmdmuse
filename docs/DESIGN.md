対象バージョン: `main` (2026-09-05 時点)
構成は [arc42](https://arc42.org/overview/) の抜粋。
開発の進め方は [CONTRIBUTING.md](../CONTRIBUTING.md) を参照。

---

## 1. 目的と品質目標

### 1.1 目的

シェルの行の中に `AI(やりたいこと)` と書くと、その部分だけが実際に動くコマンドに置き換わる。
行の前後はそのまま残るので、パイプの途中にも書ける。

```
cmd> cat server.log | AI(直近のエラーだけ抜き出したい) | less
cmd> cat server.log | grep -i error | tail -20 | less
```

### 1.2 品質目標

優先順位を付けてある。競合したときは上を採る。

| 順 | 品質 | なぜこの順位か |
|---|---|---|
| 1 | **安全性** | モデルが書いた文字列を cmdmuse が自動実行する箇所がある。ここで破壊的な操作が一度でも走れば、この道具は使えなくなる |
| 2 | **応答時間** | 「手が止まって5秒で候補が出る」ことが利用体験の前提。待たされるならシェルを直接使ったほうが速い |
| 3 | **説明の正確さ** | フラグの説明が誤っていると、利用者は確認したつもりで誤ったコマンドを実行する。無説明より害が大きい |
| 4 | **移植性** | Linux / Windows / macOS で同じ単一バイナリが動くこと |

## 2. 制約

設計で動かせない前提。

| 制約 | 内容 | 由来 |
|---|---|---|
| 単一バイナリ | 実行時ランタイムも設定ファイルも要求しない | 要件 |
| ログインシェルを置き換えない | cmdmuse は `$SHELL` の前段に立つだけ。確定した行は `$SHELL -c` に渡して実行する | 要件 |
| OpenAI 互換 API のみ | 使うのは `GET /models` と `POST /chat/completions` の2つ | ローカルのサーバーでもクラウドでも動かすため |
| モデル固有機能を使わない | tool calling / structured output / ストリーミングは使わない | 同上 |
| シェルを補助に使わない | 補完も probe (用語集参照) も、編集中の行や生成物をシェルに渡さない | 品質目標1 |
| 画面を占有しない | 端末の代替画面バッファに入らない | 実行結果が通常のシェルと同じようにスクロールバックへ残る必要がある |
| 処理内で実行するコマンドは副作用がないもの | `--help` / `man` / probe / `tmux capture-pane` | 品質目標1 |

## 3. コンテキストと範囲

### 3.1 外部との境界

```mermaid
flowchart LR
    U[利用者 / 端末] <--> C[cmdmuse]
    C -->|GET /models<br/>POST /chat/completions| L[LLM エンドポイント]
    C -->|確定した行を -c で渡す| S["$SHELL"]
    C -->|probe / --help| P[PATH 上のコマンド]
    C -->|読み書き| F["ファイルシステム<br/>~/.cmdmuse_history"]
    C -.任意.-> M[man]
    C -.任意.-> T[tmux]
```

| 相手 | 向き | やりとりする内容 | 必須 |
|---|---|---|---|
| 利用者 / 端末 | 双方向 | キー入力と画面表示 | 必須 |
| LLM エンドポイント | 送受信 | HTTP。起動時の疎通確認とモデル名解決、候補生成 / 解説 / 深堀り | 必須 |
| `$SHELL` | 起動 | 確定した行。端末をそのまま渡すので `vim` や `less` も動く | 必須 |
| ファイルシステム | 読み書き | 補完のためのディレクトリ読み取り、履歴の読み書き | 必須 |
| `PATH` 上のコマンド | 起動 | probe の実行、`--help` の取得 | 必須 |
| `man` | 起動 | フラグ定義の取得。無ければ `--help` だけで済ませる | 任意 |
| `tmux` | 起動 | `capture-pane` で直前の画面を取る。無ければ履歴ファイルで代替 | 任意 |

### 3.2 範囲外

- シェルの設定 (エイリアス、シェル関数、`.bashrc` 等) の解釈
- ジョブ制御 (`&`、`fg`、`bg`、`Ctrl+Z`)
- 会話の永続化。問い合わせは1回ごとに独立している
- モデルの学習・微調整

## 4. 解決戦略

品質目標ごとに、何を選んだか。

| 品質目標 | 取った方針 |
|---|---|
| 安全性 | モデルの出力を「cmdmuse が自動実行する文字列 (probe)」と「利用者が選んで実行する文字列 (候補)」に分ける。前者は許可リストで実行範囲を限定し、後者は `Enter` を経ずに実行しない |
| 応答時間 | 生成以外で待たせない。`PATH` の走査は起動直後に先読みし、probe は候補を表示してから非同期で走らせ、補完は `tea.Cmd` で入力処理と分離する |
| 説明の正確さ | モデルに知識を出させない。`--help` と `man` から取った実定義を入力に注入し、要約だけをさせる |
| 移植性 | cgo と外部ランタイムを使わない。OS 差は実行シェルの分岐 (`$SHELL` / `powershell.exe`) と `internal/session` の取得元だけに閉じ込める |

## 5. 構成要素

### 5.1 依存関係

```mermaid
flowchart TD
    main --> editor
    main --> llm
    main --> session
    main --> complete
    editor --> complete
    editor --> expand
    editor --> llm
    editor --> probe
    editor --> spec
    llm --> core
    probe --> core
    spec --> core
    session --> core
```

- `core` は共有する型だけを持ち、他の `internal` を参照しない
- `editor` 以外のパッケージは互いを知らない。組み合わせるのは `editor` と `main` の役目
- `complete` と `expand` は `core` にも依存しない (文字列だけを扱う)

### 5.2 責務

| パッケージ | 責務 | 主な入口 |
|---|---|---|
| `main` | REPL ループ。1行読む → `cd` / `exit` を自前で処理 → 残りを `$SHELL` に渡す | `main()`, `runInShell()` |
| `internal/editor` | 行エディタ。bubbletea を代替画面なしで動かし、候補・補完・履歴・深堀りを1行の下に描く | `Model`, `Result` |
| `internal/expand` | 行の中から `AI(...)` を切り出す。引用符と入れ子の括弧を解釈し、閉じていなければ切り出さない | `Find()`, `Replace()`, `HasMarker()` |
| `internal/llm` | モデルへの問い合わせ。候補生成 / 解説 / 深堀りの3種類のプロンプトと、応答 JSON の復元 | `New()`, `Client.Probe()`, `Client.Candidates()`, `Client.Explain()`, `Client.Followup()` |
| `internal/probe` | probe の実行 (許可リスト方式) と、候補コマンドの副作用の静的判定 | `NewRunner()`, `Runner.RunAll()`, `Classify()` |
| `internal/spec` | `--help` と `man` を実行して統合し、フラグの実定義を取り出す | `NewLookup()`, `Lookup.Annotate()`, `Split()` |
| `internal/complete` | 補完の候補を作る。`PATH` の走査とディレクトリの読み取りだけを使う | `Complete()`, `WarmPathCache()` |
| `internal/session` | 直前のシェル操作を集める。tmux → PSReadLine → 履歴ファイル → 無し、の順に試す | `Capture()` |
| `internal/core` | パッケージ間で共有する型 | `Candidate`, `Precond`, `RiskLevel`, `SessionContext` |

## 6. ランタイム

### 6.1 `AI(...)` の展開

```mermaid
sequenceDiagram
    participant U as 利用者
    participant E as editor
    participant L as llm
    participant M as モデル
    participant P as probe
    participant S as spec

    U->>E: AI(やりたいこと) を打つ
    Note over E: 5秒キー入力が無い (Enter でも即時)
    E->>L: 行の前後 + セッション文脈を渡す
    L->>M: 候補生成のプロンプト
    M-->>L: JSON 配列 (3〜5件)
    L-->>E: 候補 (コマンド / 前提 / 軸)
    E-->>U: 候補を表示 (probe はまだ未判定)
    Note over E,S: ここから非同期。表示は止めない
    E->>S: 全候補のフラグの実定義を引く
    S-->>E: 定義
    E->>P: 全候補の前提を検証
    P-->>E: ✓ / ⚠
    E-->>U: 印と副作用の重さを表示に反映
    Note over E: 候補の選択が 300ms 止まったら
    E->>L: 選択中の候補を、定義だけを根拠に要約させる
    L-->>E: 解説
    E-->>U: 解説を表示
```

候補は検証を待たずに先に表示する。検証の完了を待つと、体感の待ち時間が生成時間ぶん延びる。

定義の取得・副作用の判定・probe の実行は1本の非同期処理にまとめてある (`enrichCmd`)。
解説だけは別で、候補の選択が 300ms 止まってから投げる。
`Tab` で候補を素早く送っている間に毎回投げると、使われない解説の生成が積み上がる。

### 6.2 補完

1. 利用者が `AI(...)` を含まない行を打つ
2. `editor` が `tea.Cmd` で `complete.Complete()` を呼ぶ (入力処理は止めない)
3. 結果が返ると、カーソルが行末にある場合だけ続きを薄い色で表示する
4. `Tab` で候補を送り、選択中のものが白く表示される (行にはまだ入っていない)
5. `Enter` で行に取り込む。実行はしない。もう一度 `Enter` で実行

取り込みを2段階に分けているのは、外れた提案を `Esc` で捨てられるようにするため。

### 6.3 行の実行

1. `Enter` で行が確定する
2. `main` が履歴に積む
3. `exit` / `quit` なら終了、`cd` なら `os.Chdir` で自分が移動する
   (子プロセスで `cd` しても親には効かないため)
4. それ以外は `$SHELL -c <行>` (Windows は `powershell.exe -NoProfile -Command <行>`)
   標準入出力を継承するので、対話的なコマンドもそのまま動く

## 8. 横断的関心事

### 8.1 安全性

cmdmuse の中には、モデルが書いた文字列が3系統ある。扱いを分けている。

| 系統 | 誰がいつ実行するか | 守り方 |
|---|---|---|
| **probe** | cmdmuse が自動で。利用者の確認を挟まない | 許可リストで実行範囲を限定 (ADR-1) |
| **候補のコマンド** | 利用者が選んで `Enter` を押したときだけ | 自動実行しない。副作用の重さを `[書き込み]` / `[破壊的]` として選ぶ前に見せる |
| **解説の文章** | 実行しない (表示のみ) | 実定義だけを根拠にさせる (ADR-3) |

編集中の行も、補完のためにシェルへ渡すことはない (ADR-2)。

### 8.2 エラー処理

失敗の種類ごとに、どこで止めるかを変えている。

| 失敗 | 扱い |
|---|---|
| 起動時に LLM へ接続できない | 標準エラーに理由と `CMDMUSE_BASE_URL` の指定方法を出して終了 (exit 1) |
| 候補生成に失敗した | 行の下に `✗ <理由>` を出す。**打った行は消さない** |
| モデルの応答が JSON でない | コードフェンスや前後の地の文があれば取り除く。途中で切れた配列は、閉じている要素だけを救出する |
| probe が失敗 / 実行できない | 候補は消さない。`⚠` を付けて理由を下に出し、選択はできるままにする |
| フラグの実定義が取れない | 「取得できませんでした」と書かせる。推測させない |
| セッション文脈が取れない | `Source="none"` として文脈なしで続行する |

### 8.3 応答時間の設計

| 待つもの | 上限 | 理由 |
|---|---|---|
| `AI(...)` を打ってから展開開始まで | 5秒 | 打ち終わりの判定。`Enter` で待たずに開始できる |
| 起動時の疎通確認 | 15秒 | 起動を長く止めない |
| 候補生成 / 深堀り | 120秒 | 生成そのもの。`Ctrl+C` で中断できる |
| 解説 | 90秒 | 同上 |
| probe 1件 | 4秒 | 候補5件ぶん走らせても表示を止めない |
| 定義取得 + 副作用判定 + probe 全件 | 20秒 | 上の合計に上限を置く |
| `--help` / `man` 1回 | 3秒 | 応答しないコマンドで止まらないため |
| セッション文脈の収集 | 全体8秒 / 1コマンド3秒 | 起動を止めないため |
| 解説を始めるまでの猶予 | 300ms | 候補を素早く送っている間は解説を投げない |

`PATH` の走査は起動直後に別の goroutine で先読みする。最初のキー入力でこれを待つと、
`PATH` の項目が多い環境 (WSL から Windows 側の `PATH` を継承した場合など) で
数秒間キー入力が固まる。

### 8.4 並行性

非同期の処理はすべて bubbletea の `tea.Cmd` として投げ、結果は `Update` にメッセージとして返る。
`Model` は世代番号 `seq` を持ち、行が変わるたびに進める。返ってきた結果の `seq` が
現在と違えば捨てる。これで、古い問い合わせの結果が新しい行を上書きすることを防ぐ。

`tea.Cmd` を返す関数は値レシーバで書く。`return m, m.someCmd(...)` は `m` を先に複製するため、
ポインタレシーバで書き込んでも失われる。キャンセル関数は戻り値で返している。

## 9. アーキテクチャ決定

各決定は 状況 / 決定 / 検討した代替案 / 結果 の順で書く。

### ADR-1 probe をシェルに通さず、許可リストで実行する

**状況** — 候補が使えるかどうかを確かめるため、モデルに短い確認コマンド (probe) を書かせ、
cmdmuse がそれを実行する。実行は候補を表示する前に自動で走り、利用者の確認を挟まない。
モデルの出力は制御できないので、`rm -rf /` が来ることを前提に設計する必要がある。

**決定** — 実行の側で範囲を限定する。

- `exec` に引数を配列のまま渡す。文字列をシェルに解釈させないので、`;` や `` ` `` は
  記号のままで、区切りにも展開にもならない
- コマンド名を許可リストで限定する。状態を読むだけのものしか登録しない
- サブコマンドも個別に許可する。`git config --get` は通すが `git config --global x y` は通さない
- 破壊的なフラグを個別に除く (`find -delete`、`find -exec` など)
- `test` / `command -v` / `which` / `type` は外部プロセスを起こさず Go 側で判定する

許可リストに無いものが来たら実行せず、その前提は「確認できませんでした」として扱う。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| 危険なパターンを拒否リストで弾く | 網羅できない。1つ漏れれば破られる。許可リストなら漏れは「実行されない」側に倒れる |
| 実行前に利用者へ確認を求める | 候補5件ぶんの確認が出る。5秒で候補が並ぶ体験が崩れる |
| コンテナや `chroot` の中で実行する | 単一バイナリという制約に反する。probe は現在のディレクトリの状態を見る必要もある |
| probe を廃止し、実行可能性の検証をやめる | 要件そのものを落とすことになる |

**結果**

- 得るもの — モデルが何を書いても、許可リストの外は実行に到達しない。
  `rm -rf /` や `` `rm -rf /` `` を含む26パターンで固定してある
  (`internal/probe/probe_test.go` の `TestRejectsDangerous`)
- 代償1 — 許可リストを人が保守する。新しいコマンドを足すたびに副作用の有無を確かめる必要がある
- 代償2 — シェルを通さないのでグロブが展開されない。`filepath.Glob` で自前で展開している
- 代償3 — 検証できる前提の種類が許可リストの範囲に限られる

### ADR-2 補完を compgen に委ねない

**状況** — 補完の候補は bash に計算させることができる (`compgen`)。
シェルの補完設定を利用でき、実装も小さくなる。

**決定** — 使わない。`PATH` を走査してコマンド名を集め、`os.ReadDir` でディレクトリを読む。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| `compgen` に委ねる | 編集中の行がそのまま `bash -c` の引数になり、行の中身をシェルが解釈する。`echo $(date)` まで打った状態で `Tab` を押すと `date` が実際に実行される |
| `compgen` に渡す前に行をエスケープする | 何を安全に渡せるかの判断を毎回行うことになる。判断を間違えれば実行される |
| 補完機能を持たない | シェルの代わりに使う道具なので、補完が無いと使えない |

**結果**

- 得るもの — 何を打っていても `Tab` で何かが実行されることはない
- 代償1 — シェルのエイリアス、シェル関数、コマンド固有の補完 (`git checkout <branch>` など) が出ない
- 代償2 — `PATH` の走査を自前で持つ必要がある (起動時の先読みが要る。8.3 参照)

### ADR-3 フラグの実定義を注入し、要約だけをさせる

**状況** — 候補が使うフラグの意味を説明する必要がある。
モデルに直接書かせると、それらしいが誤った説明が出る。
利用者は「説明を読んで確認した」つもりで誤ったコマンドを実行することになり、
説明が無い場合より害が大きい。

**決定** — `--help` と `man` の両方を実行して出力を統合し、取れた定義だけをモデルへの入力に混ぜる。
プロンプトでは「この定義だけを根拠に要約せよ」と指示し、
定義が取れなかったフラグには「取得できませんでした」と書かせる。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| モデルの知識だけで書かせる | 誤りを構造的に防げない |
| `--help` だけを使う | 足りない。GNU find の `--help` は要約しか出さず、`-name` の説明は man にしかない |
| フラグの説明機能を持たない | 要件 (引数の解説) を落とすことになる |

**結果**

- 得るもの — 説明の根拠が手元のコマンド自身になる。定義が無ければ何も書かれない
- 代償1 — `--help` と `man` の実行が要る。1コマンドあたり最大2プロセス
- 代償2 — man の無い環境では説明が薄くなる
- 代償3 — 束ねた短いフラグ (`-lah`) を分解する処理が要る

### ADR-4 端末の代替画面に入らず、行エディタとして動く

**状況** — bubbletea のような TUI ライブラリは通常、端末の代替画面バッファに入って画面全体を描く。
`vim` や `less` と同じ挙動で、終了すると元の画面に戻る。

**決定** — 代替画面に入らない。プロンプト1行と、その下に候補や補完を描く。
確定した行の実行結果は端末にそのまま流す。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| 全画面 TUI にする | 実行結果が終了時に消える。シェルの代わりとして使えない |
| 別ペインに候補を出す | tmux などの多重化ソフトに依存する。単一バイナリで完結しない |

**結果**

- 得るもの — 通常のシェルと同じように、入力も実行結果もスクロールバックに残る
- 代償1 — 再描画を自分で管理する必要がある。描画が保留されることがあり、
  端末を取得しても何も見えない状態が起こりうる (キーを1つ送ると現れる)
- 代償2 — 候補の一覧が端末の高さに収まらない場合、自前で窓を動かす必要がある

### ADR-5 候補の重複判定に「コマンド名 + サブコマンド + 最初のフラグ」を使う

**状況** — 要件は「アプローチの異なる候補」を出すこと。
プロンプトで指示しないと、モデルは3〜5件すべてを同じコマンドのフラグ違いで埋める。
重複を機械的に除く必要がある。

**決定** — 各候補に戦略ラベル (`strategy`) を持たせ、同じラベルの候補を捨てる。
ラベルがモデルの書式に合わない場合は、コマンドから
「コマンド名 + サブコマンド + 最初のフラグ」で生成し直す。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| コマンド名だけで判定する | `git merge --no-ff` と `git merge --squash` が同一視され、片方が消える。この2つは選択肢として別物 |
| コマンド文字列全体で判定する | フラグの順序や引数名が違うだけで別物として通ってしまう |
| 重複を除かない | 全候補が同じコマンドのフラグ違いになる |

**結果**

- 得るもの — `tr` / `paste` / `awk` / `xargs` のように系統の違うコマンドが並ぶ
- 代償 — 判定が構文的なので、実質同じことをする別コマンドは重複として除けない

### ADR-6 行に打てる文字を操作キーに割り当てない

**状況** — 候補の深堀りや候補の選択に、1打鍵で届くキーを割り当てたい。

**決定** — 行に打ち込める文字 (`?` や数字など) は操作キーにしない。
深堀りを開くキーは `Ctrl+O` にしてある。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| `?` で深堀りを開く | 正規表現やグロブで `?` を使う行が打てなくなる |
| 候補が出ているときだけ文字キーを操作に使う | 状態によって同じキーの意味が変わる。`tail -20` のような行を候補表示中に編集できなくなる |

**結果**

- 得るもの — どんな行でも打てる
- 代償 — 操作キーが修飾キー付きになり、1打鍵では届かない

> **未解決:** `--help` と画面下部のヒント行は `1-9` での候補選択を案内しているが、
> 実装が無い。この ADR と衝突しない形 (候補表示中に限る) で実装するか、
> 案内を消すかが決まっていない。[#6](https://github.com/gimenorum/cmdmuse/issues/6)

### ADR-7 `Ctrl+C` は状態によって捨てる範囲を変える

**状況** — 候補が出るまでに5秒 + 生成時間がかかる。
`Ctrl+C` で毎回行ごと捨てると、その待ち時間を1打鍵で失うことになる。

**決定** — 押した時点の状態で捨てるものを変える。

| そのときの状態 | 捨てるもの | 残るもの |
|---|---|---|
| 候補を生成中 | 生成の待ち | 打った行はそのまま |
| 候補が画面に出ている | 候補の一覧 | 選んでいた候補が行に入ったまま |
| それ以外 | 行そのもの | — |

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| 常に行ごと捨てる (シェルの `Ctrl+C` と同じ) | 待って出てきた候補を1打鍵で失う |
| 生成の中断に別のキーを割り当てる | 中断は `Ctrl+C` だという期待に反する |

**結果**

- 得るもの — 待ち時間を捨てずに、生成だけをやり直せる
- 代償 — 同じキーの結果が状態で変わる。シェルの `Ctrl+C` とは挙動が違う

### ADR-8 モデルには行の断片だけを書かせる

**状況** — `AI(...)` は行のどこにでも書ける。
`ls | AI(...) | less` のようにパイプの途中に置かれることもある。
モデルに目的だけを渡すと、行全体を書こうとして `ls | AI(...)` に対して
`ls | tr ...` のように `ls` を二重に書いてくる。

**決定** — `AI(...)` の前後にある文字列を `LineContext` としてモデルに渡し、
「置き換わるのはこの部分だけなので断片を書く」「前がパイプなら標準入力を受け取る」と指示する。

**検討した代替案**

| 案 | 採らなかった理由 |
|---|---|
| 行全体を書かせて置き換える | 要件 (`AI(...)` の部分だけが置き換わる) に反する。前後に書いたものが消える |
| 生成後に重複を機械的に除く | 何が重複かの判定が構文解析に近くなる。パイプ以外の形も扱えない |

**結果**

- 得るもの — パイプの途中でも、コマンド置換の中でも成立する
- 代償 — プロンプトが長くなる。前後の文脈を毎回送るぶん入力トークンが増える

## 10. 品質要件

品質目標を、確かめられる形にしたもの。

| # | 品質 | シナリオ | 現状 |
|---|---|---|---|
| Q1 | 安全性 | モデルが probe として `rm -rf /` を返しても、実行に到達しない | `TestRejectsDangerous` の26パターンで固定 |

| Q6 | 説明の正確さ | 定義が取れなかったフラグに、意味が書かれない | プロンプトで指示。**自動検証は無い** |
| Q7 | 移植性 | 5構成でビルドが通る | CI (`.github/workflows/ci.yml`) |

## 11. リスクと技術的負債

| # | 内容 | 影響 | 現状 |
|---|---|---|---|
| R1 | probe の許可リストは人が保守する。副作用のあるコマンドを足すと防御が崩れる | 高 | CONTRIBUTING で確認を義務付け。`probe_test.go` で回帰を防ぐ |
| R2 | 候補コマンドの危険度判定 (`internal/probe/risk.go`) はコマンド名とサブコマンドの表に依存する。表に無いものは `[書き込み]` も `[破壊的]` も付かない | 中 | 未対応。表示が控えめに外れる方向なので、実行の安全性には影響しない |
| R3 | `internal/editor` と `internal/session` にテストが無い | 中 | 未対応 |
| R4 | 履歴 `~/.cmdmuse_history` は平文。パスワードを含む行も残る | 中 | パーミッション `600` のみ。除外規則は無い |
| R5 | モデルの応答が JSON でないときの回復は、プロンプトと後処理に依存する | 中 | 途中で切れた配列の救出のみ実装 |
| R6 | `--help` と画面下部のヒント行が、実装の無い `1-9` / `←→` を案内している | 低 | [#6](https://github.com/gimenorum/cmdmuse/issues/6) |
| R7 | `Ctrl+D` が「行が空のとき終了」であることを、起動メッセージと `--help` が書いていない | 低 | [#3](https://github.com/gimenorum/cmdmuse/issues/3) |
| R8 | プロンプトに作業ディレクトリが出ない | 低 | [#5](https://github.com/gimenorum/cmdmuse/issues/5) |
| R9 | `PATH` の項目が多い環境で走査に数秒かかる (WSL から Windows 側の `PATH` を継承した場合など) | 低 | 起動時の先読みで隠している。走査そのものは速くなっていない |

## 12. 用語集

| 用語 | 意味 |
|---|---|
| **候補** | `AI(...)` 1回の問い合わせに対してモデルが返すコマンドの案。画面に3〜5件並び、利用者が1件を選ぶ |
| **probe** | 候補が使えるかどうかを確かめるための短いコマンド。モデルが候補と一緒に書き、**cmdmuse が利用者に断らずに実行する**。例: `git rev-parse --git-dir`、`command -v rename` |
| **前提条件 (Precond)** | 候補が成立するために満たされている必要がある条件と、それを確かめる probe の組 |
| **戦略ラベル (Strategy)** | 候補どうしが同じアプローチかどうかを判定するためのラベル。重複排除に使う |
| **軸 (Axis)** | 候補が他の候補とどこで違うかを一語で表したもの。画面の右端に出る (例: 再帰的、組み込み、専用ツール) |
| **補完** | `AI(...)` を使わずに普通のコマンドを打っているとき、コマンド名やパスの続きを cmdmuse が推測して薄く表示するもの。モデルには問い合わせない |
| **セッション文脈** | 直前のシェル操作。tmux の画面、PSReadLine の履歴、シェルの履歴ファイルのいずれかから取り、候補生成の入力に混ぜる |
