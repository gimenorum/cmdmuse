# 設計

cmdmuse を**なぜこの作りにしたのか**を書く。
開発の進め方は [CONTRIBUTING.md](../CONTRIBUTING.md) を参照。

## 何が起きているか

利用者が1行打ってから、そのコマンドが実行されるまでの順序。

1. `main.go` の REPL ループが、`internal/editor` に1行ぶんの入力を読ませる
2. 行の中に `AI(...)` があり、キー入力が5秒止まると、`internal/llm` がモデルに問い合わせる
3. モデルは候補を3〜5件返す。1件は「実行するコマンド」と
   「そのコマンドが使えるための前提」の組になっている
4. `internal/probe` がその前提を確かめ、候補ごとに `✓` / `⚠` を付ける
5. 利用者が1件選んで `Enter` を押すと、`main.go` がその行を `$SHELL` に渡して実行する

cmdmuse は vim や less のように画面全体を占有しない。
プロンプトも実行結果も、通常のシェルと同じように端末へ流れ、スクロールバックに残る。

## 用語

**候補** — `AI(...)` 1回の問い合わせに対してモデルが返すコマンドの案。
画面に3〜5件並び、利用者が1件を選ぶ。

**probe** — 候補が使えるかどうかを確かめるための短いコマンド。
モデルが候補と一緒に書き、**cmdmuse が利用者に断らずに実行する**。
「ここは git のリポジトリか」なら `git rev-parse --git-dir`、
「`rename` が入っているか」なら `command -v rename`。

**補完** — `AI(...)` を使わずに普通のコマンドを打っているとき、
コマンド名やパスの続きを cmdmuse が推測して薄く表示するもの。
モデルには一切問い合わせず、`PATH` とディレクトリの中身を読んで作る。

## パッケージ構成

```
internal/complete 補完の候補を作る (PATH の走査とディレクトリの読み取り)
internal/expand   行の中から AI(...) を切り出す (引用符と入れ子の括弧を解釈する)
internal/editor   行エディタ。bubbletea を画面占有なしで使う
internal/llm      モデルへの問い合わせ。候補生成 / 解説 / 深堀りの3種類
internal/spec     --help と man を統合して、フラグの実定義を取り出す
internal/probe    probe の実行と、候補が持つ副作用の判定
internal/session  tmux や履歴から、直前の入出力を集める
internal/core     パッケージ間で共有する型
```

## probe の実行を制限する

probe はモデルが書いた文字列で、cmdmuse はそれを自動で実行する。
候補を画面に並べる前に、`✓` / `⚠` を決めるために走らせる。
利用者の確認を挟まないので、ここが cmdmuse で一番危ない場所になる。

そこで、**モデルの書き方を信用する代わりに、実行できる範囲そのものを制限した。**

- **シェルを通さない** — `exec` に引数を配列のまま渡す。文字列をシェルに解釈させないので、
  `;` や `` ` `` は記号のままで、区切りにも展開にもならない
- **コマンド名を許可リストで限定する** — 状態を読むだけのものしか登録していない
- **サブコマンドも個別に許可する** — `git config --get` は通すが `git config --global x y` は通さない
- **破壊的なフラグを個別に除く** — `find -delete` や `find -exec` など

許可リストに無いものをモデルが書いてきたら、cmdmuse はそれを実行せず、
その前提は「確認できませんでした」として扱う。
`rm -rf /` や `` `rm -rf /` `` を含む26パターンが実行に到達しないことを、
`internal/probe/probe_test.go` の `TestRejectsDangerous` で固定してある。

probe とは別に、**cmdmuse は候補のコマンド自体を自動実行しない。**
利用者が選んで `Enter` を押した1件だけを `$SHELL` に渡す。

## 補完を bash に任せない

補完の候補は bash に計算させることができる (`compgen`)。cmdmuse はこれを使っていない。
`compgen` に渡すと編集中の行がそのまま `bash -c` の引数になり、行の中身をシェルが解釈する。
`echo $(date)` まで打った状態で Tab を押すと `date` が実際に実行される、という類のことが起きる。

cmdmuse は `PATH` を走査してコマンド名を集め、`os.ReadDir` でディレクトリを読む。
これで同じ候補が作れるので、行をシェルに渡す必要がない。

## フラグの意味をモデルに書かせない

cmdmuse は候補が使うフラグについて、`--help` と `man` の両方を実行して出力を統合する。
片方だけでは足りないことが多く、たとえば GNU find の `--help` は要約しか出さず、
`-name` の説明は man にしかない。`-lah` のように束ねた短いフラグは、
`-l` `-a` `-h` に分解してから個別に引く。

取れた定義だけをモデルへの入力に混ぜ、「この定義だけを根拠に要約せよ」と指示する。
定義が取れなかったフラグには「取得できませんでした」と書かせる。
ここを緩めると、モデルは記憶から書き始め、それらしいが間違った解説が出るようになる。

## 候補には違うコマンドを並べさせる

ここでいう候補とは、`AI(...)` 1回の問い合わせでモデルが返す3〜5件のことを指す。

プロンプトで何も指示しないと、モデルは3〜5件すべてを**同じコマンドのフラグ違い**で埋めてくる。
`tr` / `paste` / `awk` / `xargs` のように系統の違うコマンドを例として挙げ、
「この中から選べ」と書くと、選択肢として意味のある散り方をする。

候補どうしが同じものかどうかは、「コマンド名 + サブコマンド + 最初のフラグ」で判定する。
最初のフラグまで見ないと `git merge --no-ff` と `git merge --squash` が同じものとみなされ、
片方が重複として捨てられる。

## パイプの前後をモデルに伝える

`AI(...)` は行のどこにでも書ける。`ls | AI(...) | less` のようにパイプの途中に置かれることもある。

このとき cmdmuse は、`AI(...)` の前後にある文字列を `LineContext` としてモデルに渡し、
「置き換わるのはこの部分だけなので断片を書く」「前がパイプなら標準入力を受け取る」と指示する。
これが無いと、モデルは行全体を書こうとして、`ls | AI(...)` に対して `ls | tr ...` のように
`ls` を二重に書いてくる。

## 文字キーを操作に割り当てない

行に打ち込める文字 (`?` や数字など) は、操作キーに使わない。
候補の深堀りを開くキーが `?` ではなく `Ctrl+O` なのはこのため。
`?` に割り当てると、正規表現やグロブで `?` を使う行が打てなくなる。

## Ctrl+C で一度に全部を捨てない

`Ctrl+C` は、押した時点の状態によって捨てるものを変える。

| そのときの状態 | 捨てるもの | 残るもの |
|---|---|---|
| 候補を生成中 | 生成の待ち | 打った行はそのまま |
| 候補が画面に出ている | 候補の一覧 | 選んでいた候補が行に入ったまま |
| それ以外 | 行そのもの | — |

どの状態でも行ごと捨てる作りにすると、5秒待って出てきた候補を1回のキーで失い、
打ち直しになる。
