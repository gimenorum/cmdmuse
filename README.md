# cmdmuse

行の中に書いた `AI(...)` を、実際に動くコマンドへ置き換えるシェルフロントエンド。

```
cmd> cat server.log | AI(直近のエラーだけ抜き出したい) | less
     ↓ 手が止まって5秒
cmd> cat server.log | grep -i error | tail -20 | less
```

`AI(...)` の部分**だけ**が置き換わり、前後はそのまま残る。パイプの途中にも書ける。

自然言語からコマンドを作るツールは既にあるが、候補が同じコマンドのフラグ違いばかりになる、
入っていないコマンドを勧めてくる、フラグの説明が実物と違う、のどれかで外れることが多い。
cmdmuse は**道具ごと違う候補を出す / 実行できるかを先に確かめる / フラグの説明は
`--help` と `man` の実定義だけを根拠にする**の3つを揃えている。

## 動くところ

```
cmd> AI(拡張子を一括で変えたい)
     ↓
cmd> rename 's/\.txt$/\.log/' *.txt
  候補 1/5
 ▸ ⚠1 rename 's/\.txt$/\.log/' *.txt                 専用ツール    [書き込み]
   ✓2 find . -name '*.txt' -exec sh -c 'mv ...' _ {} \;  再帰的
    3 for f in *.txt; do mv "$f" "${f%.txt}.log"; done   組み込み
   ✓4 perl -MFile::Find -e '...'                        スクリプト言語
   ✓5 printf '%s\n' *.txt | sed ... | xargs ...         文字列処理
  ⚠ rename コマンドが使える — rename が PATH にありません
  Tab 候補   1-9 選択   Ctrl+O 深堀り   Enter 実行   Esc 元に戻す
```

- **`✓` / `⚠`** — 前提条件を副作用のないコマンドで検証した結果。`⚠` は理由が下に出る
- **`[書き込み]` / `[破壊的]`** — 副作用の重さ。実行はされないが、選ぶ前に分かる
- **右端の短い語** — 候補どうしの違いがどの軸にあるか
- **フラグの説明** — `--help` と `man` から取った実定義。LLM には要約だけさせる

## 使い方

```
cmdmuse
```

`cmd>` プロンプトが出る。ここは普通のシェルとしても使えて、`ls -la` でも `cd ..` でも打てば動く。
分からない部分だけ `AI(やりたいこと)` と書くと、5秒後にコマンドへ変わる。

| キー | 動作 |
|---|---|
| 5秒アイドル | `AI(...)` を候補に置換 |
| `Enter` | 補完を取り込む / 未展開の `AI(...)` を待たずに展開 / それ以外は実行 |
| `Tab` `Shift+Tab` | 候補・補完を次へ / 前へ |
| `↑` `↓` | 候補表示中は候補を選ぶ / 補完一覧では1行ぶん移動 / どちらも無ければ履歴 |
| `←` `→` | 補完一覧では候補を選ぶ / それ以外はカーソル移動 |
| `Esc` | 補完一覧を閉じる / 候補を捨てて `AI(...)` の行に戻す |
| `Ctrl+O` | 選択中の候補に追加で質問する (例: 失敗したら戻せる?) |
| `Ctrl+C` | 生成中なら生成のみ中止 / 候補表示中なら候補のみ畳む / それ以外は行を破棄 |
| `Ctrl+D` | **行が空のとき**終了。文字があればカーソル位置を1文字削除 (bash と同じ) |
| `exit` `quit` | 終了 |

画面下部のヒントに出る `1-9 選択` と、`--help` の `←→` は**まだ実装されていない**
([#6](https://github.com/gimenorum/cmdmuse/issues/6))。候補が出ているときに数字を押すと
行に入力されてしまい、候補が消える。候補の選択は `Tab` か `↑↓` を使うこと。

行編集は Readline 風のキーがそのまま使える。`Ctrl+A` / `Ctrl+E` で行頭・行末、
`Ctrl+W` で直前の語を削除、`Ctrl+U` / `Ctrl+K` でカーソルより前・後ろを削除。

候補が自動実行されることはない。`Enter` を押すまで何も起きない。

### 打ちながら続きが見える

`AI(...)` を使わない普通の入力では、続きが薄い色で先に出る。

```
cmd> cd ~/cmdmuse/inter nal/          nal/ が薄く出ている
        Tab             ↓
cmd> cd ~/cmdmuse/internal/           白くなる (まだ行には入っていない)
        Enter           ↓
cmd> cd ~/cmdmuse/internal/           行に取り込まれる
        Enter           ↓             実行
```

取り込みを2段階に分けているのは、外した提案を `Esc` で捨てられるようにするため。
`Tab` で確定して即実行だと、違う候補だったときに実行してから気づくことになる。

提案はカーソルが行末にあるときだけ出る。行の途中は編集中とみなして黙る。

## 導入

```
go install github.com/gimenorum/cmdmuse@latest
```

ソースから入れるなら Go 1.27 以上。

```
git clone https://github.com/gimenorum/cmdmuse.git
cd cmdmuse
go build -trimpath -ldflags="-s -w" -o cmdmuse .
```

対応するのは `linux/amd64` `linux/arm64` `windows/amd64` `darwin/amd64` `darwin/arm64`。
CI がこの5構成をビルドしている。

### 起動

```
cmdmuse            起動する
cmdmuse --help     キーと環境変数の一覧を出す
```

### 必要なもの

**OpenAI 互換のエンドポイント**が要る。ローカルの llama.cpp や sglang でも、OpenAI 自体でもよい。
使うのは `GET /models` と `POST /chat/completions` の2つだけで、streaming も tool calling も使わない。
起動時に `/models` を叩いて疎通とモデル名を確かめる。ここで失敗すると起動しない。

モデルに求めるのは2つ。**指示に従って JSON 配列を返せること**と、**生成が速いこと**。
「手が止まって5秒で候補が出る」のが前提の道具なので、候補5件ぶん (最大4096トークン) を
数秒で吐けないと体験が成立しない。ローカルで動かすなら、量子化後のサイズが VRAM に収まり、
CPU へ逃がす層が出ない構成を選ぶこと。速度を決めるのはパラメータ数ではなく、そこだった。

`tmux` と `man` は任意。`tmux` の中で起動すると画面の入出力を文脈として読み、
`man` があるとフラグの説明が厚くなる。どちらも無くても動く。

### 環境変数

| 環境変数 | 既定値 | 意味 |
|---|---|---|
| `CMDMUSE_BASE_URL` | `http://127.0.0.1:18080/v1` | OpenAI 互換エンドポイント |
| `CMDMUSE_API_KEY` | (未設定) | 空ならヘッダを付けない |
| `CMDMUSE_MODEL` | `/models` の先頭 | モデル名 |
| `SHELL` | `/bin/sh` | 確定した行の実行先。Windows では `powershell.exe` を使う |

履歴は `~/.cmdmuse_history` に平文で残る (パーミッション `600`、末尾2000件まで)。
直近20件が候補生成の文脈として LLM に渡る。

## 安全性

cmdmuse は LLM が出した文字列を実行する場所を持つ。そこは次のように閉じてある。

- **候補のコマンドは自動実行されない。** `Enter` を押すまで何も起きない
- **前提条件の検証はシェルを介さない。** `exec` に argv を直接渡すので `;` や `` ` `` は
  展開されず、読み取り専用のコマンドだけを許可リストで通す
- **補完もシェルを使わない。** `compgen` に渡すと編集中の行が `bash -c` を通ってしまう
- **フラグの説明は LLM に思い出させない。** `--help` と `man` の実定義だけを根拠に要約させる

なぜそうしているかは [docs/DESIGN.md](docs/DESIGN.md) に書いてある。

## 制限

- **シェルの設定を読まない** — エイリアスも関数も `.bashrc` も見ない。補完は PATH と
  ディレクトリの中身だけを見る
- **候補の正しさは保証しない** — 前提条件の検証は「実行できるか」であって「正しいか」ではない
