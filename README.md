# cmdmuse

行の中に書いた `AI(...)` を、実際に動くコマンドへ置き換えるシェルフロントエンド。

```
cmd> cat server.log | AI(直近のエラーだけ抜き出したい) | less
     ↓ 手が止まって5秒
cmd> cat server.log | grep -i error | tail -20 | less
```

`AI(...)` の部分**だけ**が置き換わり、前後はそのまま残る。パイプの途中にも書ける。

## なぜ作ったか

自然言語からコマンドを生成するツールは既にいくつもあるが、次の3つを同時に満たすものが見つからなかった。

- **候補が「アプローチの違う選択肢」であること** — 同じコマンドのフラグ違いではなく、`tr` / `paste` / `awk` / `xargs` のように道具ごと違うもの
- **実行できるかを事前に検証すること** — `rename` が入っていない環境で `rename` を提案しない
- **フラグの説明が正しいこと** — LLM に意味を思い出させず、`--help` / `man` の実定義だけを根拠にする

## 動くところ

```
cmd> AI(拡張子を一括で変えたい)
     ↓
cmd> rename 's/\.txt$/\.log/' *.txt
  候補 1/5
 ▸ ⚠1 rename 's/\.txt$/\.log/' *.txt                 専用ツール    [書き込み]
   ✓2 find . -name '*.txt' -exec sh -c 'mv ...' _ {} \;  再帰的
    3 for f in *.txt; do mv "$f" "${f%.txt}.log"; done   組み込み
   ✓4 perl -MFile::Find -e '...'                        スクリプト言語
   ✓5 printf '%s\n' *.txt | sed ... | xargs ...         文字列処理
  ⚠ rename コマンドが使える — rename が PATH にありません
  Tab 候補   1-9 選択   Ctrl+O 深堀り   Enter 実行   Esc 元に戻す
```

- **`✓` / `⚠`** — 前提条件を副作用のないコマンドで検証した結果。`⚠` は理由が下に出る
- **`[書き込み]` / `[破壊的]`** — 副作用の重さ。実行はされないが、選ぶ前に分かる
- **右端の短い語** — 候補どうしの違いがどの軸にあるか
- **フラグの説明** — `--help` と `man` から取った実定義。LLM には要約だけさせる

## 使い方

```
cmdmuse
```

`cmd>` プロンプトが出る。ここは普通のシェルとしても使えて、`ls -la` でも `cd ..` でも打てば動く。
分からない部分だけ `AI(やりたいこと)` と書くと、5秒後にコマンドへ変わる。

| キー | 動作 |
|---|---|
| 5秒アイドル | `AI(...)` を候補に置換 |
| `Enter` | 提案を取り込む / 未展開なら展開 / それ以外は実行 |
| `Tab` | 候補があれば切り替え、無ければ提案を仮確定 |
| `Esc` | 提案の仮確定を取り消す / `AI(...)` の状態に戻す |
| `↑↓` | 候補を切り替える / 候補が無ければ履歴をたどる |
| `1`-`9` | 候補を直接選ぶ |
| `Ctrl+O` | 選択中の候補に追加で質問する (例: 失敗したら戻せる?) |
| `Ctrl+C` | 生成中なら生成のみ中止 / 候補表示中なら候補のみ畳む |
| `Ctrl+D`, `exit` | 終了 |

候補が自動実行されることはない。`Enter` を押すまで何も起きない。

### 打ちながら続きが見える

`AI(...)` を使わない普通の入力では、続きが薄い色で先に出る。

```
cmd> cd ~/cmdmuse/inter nal/          nal/ が薄く出ている
        Tab             ↓
cmd> cd ~/cmdmuse/internal/           白くなる (まだ行には入っていない)
        Enter           ↓
cmd> cd ~/cmdmuse/internal/           行に取り込まれる
        Enter           ↓             実行
```

取り込みを2段階に分けているのは、外した提案を `Esc` で捨てられるようにするため。
`Tab` で確定して即実行だと、違う候補だったときに実行してから気づくことになる。

提案はカーソルが行末にあるときだけ出る。行の途中は編集中とみなして黙る。

## 導入

```
go install github.com/gimenorum/cmdmuse@latest
```

OpenAI 互換のエンドポイントが要る。ローカルの llama.cpp や sglang、あるいは OpenAI 自体でもよい。

| 環境変数 | 既定値 |
|---|---|
| `CMDMUSE_BASE_URL` | `http://127.0.0.1:18080/v1` |
| `CMDMUSE_API_KEY` | (未設定) |
| `CMDMUSE_MODEL` | `/models` の先頭 |

### モデル選び

応答が遅いと「5秒待って候補が出る」という体験が壊れる。手元 (RTX 5080 16GB) で条件を揃えて測った結果:

| モデル | 種別 | decode | 候補生成 |
|---|---|---|---|
| Qwen3-Coder-30B-A3B (Q3_K_XL) | MoE 活性3B | 148 tok/s | 約5秒 |
| Escha-Qwen3.8-27B (sglang) | dense | 61 tok/s | 約28秒 |
| Qwen3.8-Flash-Next 125B (IQ1_S) | MoE, 45層CPU | 29 tok/s | — |

速度を決めるのはパラメータ数ではなく **VRAM に載る割合**だった。活性パラメータの小さい MoE が
全部 GPU に載る構成が一番速い。

## 設計

```
internal/complete Tab 補完 (PATH 走査と ReadDir。シェルを介さない)
internal/expand   AI(...) の切り出し (引用符・入れ子括弧を解釈)
internal/editor   行エディタ。bubbletea を代替スクリーン無しで使う
internal/llm      候補生成 / 解説 / 深堀りの3プロンプト
internal/spec     --help と man を統合してフラグ実定義を取得
internal/probe    前提条件の検証 + 副作用の静的判定
internal/session  tmux / PSReadLine / 履歴から文脈を取得
```

### 生成物を信用しない

LLM が出した probe はそのまま実行される。したがって:

- **シェルを一切介さない** — `exec` に argv を直接渡すので、`;` や `` ` `` は展開されない
- **コマンド名の許可リスト** — 読み取り専用のものだけ通す
- **サブコマンドも個別に許可** — `git config --get` は通すが `git config --global x y` は通さない
- **破壊的フラグを個別に排除** — `find -delete` / `-exec` など

`rm -rf /` や `` `rm -rf /` `` を含む26パターンが実行に到達しないことをテストで固定してある。

補完も同じ理由でシェルを使わない。`compgen` に渡せば編集中の行が `bash -c` を通ることになり、
バッククォートやセミコロンを含む行が Tab を押しただけで実行される。PATH の走査と `os.ReadDir`
で同じことができるので、そちらで完結させている。

### フラグの意味を生成させない

`--help` と `man` の両方を読んで統合する。片方だけでは足りないことが多く、たとえば GNU find の
`--help` は要約しか出さず `-name` は man にしかない。束ねた短フラグ (`-lah`) は分解して個別に引く。

取れた定義だけを context に入れ、LLM には「この定義だけを根拠に要約せよ」と指示する。
定義が取れなかったフラグは「取得できませんでした」と書かせる。

## 制限

- **行編集は最小限** — 補完と履歴 (`~/.cmdmuse_history`) は持つが、シェルのエイリアスや関数は見ない
- **候補の正しさは保証しない** — 前提条件の検証は「実行できるか」であって「正しいか」ではない
